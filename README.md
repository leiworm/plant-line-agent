# 产线班组长 AI Agent（Plant Line Agent）

> 面向工厂班组长的产线状态问答与交接班助手。所有用户操作只在浏览器（Web）完成，全链路部署在厂内。
>
> **状态：设计稿 v0.1（未实施）** · 本仓库只含方案文档与可落地的配置骨架，不含现场数据、不含真实接口地址。

## 一句话结论

本项目的难点不在 AI，而在**数据契约**：监控系统已经算好了 KPI 和异常事件，Agent 只负责「取数 → 关联 → 解释 → 交付」，**不重算、不二次判定、不产生数字**。

## 已确认的前提（来自需求方）

| # | 前提 | 对设计的影响 |
|---|---|---|
| 1 | 现场已有监控系统，UPH / NTF / Retest 等 KPI 全部由它计算 | 不需要数采网关、点位适配、指标计算服务 |
| 2 | 数据不出工厂，本地已有可用模型 | 全链路本地；本地模型 ⇒ 少子 Agent、强工具、弱规划 |
| 3 | 实时异常也由监控系统计算得出 | 不做异常检测 / 预测 Agent，避免两套口径打架 |
| 4 | 用户端只在 Web 登录操作，无需消息旁路 | 事件只走站内 WebSocket/SSE，离屏即失联是已接受的取舍 |
| 5 | 关注点是 **Agent 框架设计**（子 Agent / SKILL / tool / MCP 的组成） | 文档重心放在部件职责、接口契约与取舍理由 |

## 四条不可妥协的原则

1. **每个数字可点回监控系统原始记录**，返回体必带 `source` + `timestamp` + `metric_version`；模型只组织语言，不产生数字。
2. **口径放在 SKILL，不写死在代码**：口径变更只改 `kpi-glossary/SKILL.md` 与 `metric_version`，Agent 框架不动。
3. **只读起步**：一期不提供任何写工具、设备控制工具、参数下发工具；写操作留到三期且必须人工确认。
4. **降级明确**：数据源不可用就显示「数据源不可用，最后更新 xx」，绝不用历史值冒充实时、绝不补全缺失数据。

## 运行形态速览

```
Web（唯一入口）
  ├─ 对话请求   → 主 Agent 路由 → 固定工作流 / 子 Agent → MCP 只读工具 → 证据组装 → 回答
  ├─ 事件驱动   → 订阅监控系统异常 → 去重/分级/节流 → 卡片 → 站内 WebSocket 推送
  └─ 定时触发   → 班前/班后 → 班次复盘 Agent → 交接班草稿（人工确认后归档）
```

> 术语假设：本文按 **NTF = No Trouble Found（送修/复测未复现）** 理解。若贵厂口径不同，只需修改 `skills/kpi-glossary/SKILL.md` 与 `config/plant-agent.yaml`，其余部件不变。详见 [待确认项](docs/01-需求说明书.md#5-假设与待确认项)。
