# 03 · 部件清单与接口

> 本文是框架的「零件图」。可直接消费的实现文件：[`agents/agent-definitions.md`](../agents/agent-definitions.md) · [`skills/`](../skills/) · [`tools/mcp-tool-schemas.json`](../tools/mcp-tool-schemas.json) · [`workflows/workflows.yaml`](../workflows/workflows.yaml) · [`config/plant-agent.yaml`](../config/plant-agent.yaml)

## 0. 部件分类速查（对应你问的「子 Agent / SKILL / tool / MCP」）

| 名称 | 管什么 | 本项目中的形态 | 类比 |
|---|---|---|---|
| **Tool（工具）** | 单个确定性动作 | 12 个只读函数，如 `get_kpi_snapshot` | 温度计、量具 |
| **MCP Server** | 把一组 Tool 接进来，并收口鉴权/限流/审计 | 4 个只读 Server | 带开关的插座 |
| **SKILL** | 该怎么做、何时用、口径与规矩 | 5 份 `SKILL.md` 纯文本 | 作业指导书 |
| **Agent** | 谁来决策 | 1 主 + 2 子 | 值班的人 |
| **工作流** | 按什么顺序调工具 | 3 条 YAML 配置 | 固定作业流程 |
| **服务** | 非智能但必需的支撑 | 上下文构建器 / 事件触发器 / 审计 / Web | 车间的水电气 |

**一句话**：Tool 给能力，MCP 给接口与边界，SKILL 给方法与口径，工作流给顺序，Agent 给判断，Web 给入口。

## 1. Agent 层（1 主 + 2 子）

完整定义见 [`agents/agent-definitions.md`](../agents/agent-definitions.md)，此处列契约。

| Agent | 输入 | 输出契约 | 可用工具白名单 | 退出条件 | 禁止事项 |
|---|---|---|---|---|---|
| `router` 主 Agent | 用户问题 + 上下文（`line_id/shift_id/班组/时间窗`） | `{route, answer, evidence[], caveats[]}` | 无直接工具调用权；只能派发 | 路由完成且答案通过证据检查 | 自行计算数值、编造数据、绕过证据检查、调用未授权 `line_id` |
| `anomaly-rca` 异常归因 | `event_id` 或 `metric + window` + 主 Agent 传来的上下文 | 四段式：`possible_causes[]` / `evidence[]` / `suggestions[]` / `unknowns[]` | `mcp-events` `mcp-orders` `mcp-knowledge` `mcp-kpi` | 证据链闭合或达到 `max_tool_calls=8` | 下结论说「一定是」、给参数调整指令、写回任何系统 |
| `shift-review` 班次复盘 | `line_id + shift_id + date` | 交接班草稿 Markdown + `open_items[]` + `evidence[]` | `mcp-kpi` `mcp-events` `mcp-orders` | 必填项齐全或明确标注缺失 | 自动归档（必须人工确认）、跨班次口径混用 |

**路由规则（写在主 Agent 定义里，不下沉给模型自由发挥）**

| 意图 | 判定 | 派发 |
|---|---|---|
| 现状 / 本班 KPI / 异常列表 / 对比 | 命中预置问法或快捷按钮 | 固定工作流 |
| 归因 / 「为什么」/ 需要查历史与 SOP | 含归因词或需 ≥4 次工具调用 | `anomaly-rca` |
| 交接班 / 本班小结 / 遗留问题 | 含复盘词或定时触发 | `shift-review` |
| 术语 / SOP 查询 | 单跳检索 | 工作流 `kpi-qa` 的检索分支 |
| 无法归类 | — | 回「我只能回答产线现状、异常、归因与交接班相关问题」，并给出快捷按钮 |

**上下文隔离**：两个子 Agent 各自独立上下文，只接收主 Agent 显式传入的结构化字段与工具返回，**不共享对话历史**（ADR-09）。

## 2. SKILL 层（5 份，纯文本、按需加载、改文本即生效）

| 技能 | 触发时机 | 内容要点 | 加载级别 |
|---|---|---|---|
| `kpi-glossary` | 任何涉及 UPH / NTF / Retest / 达成率 / 对比的问题 | 定义、分子分母、统计窗口、目标值与阈值来源、**常见误读**、口径版本 | 常驻（最优先） |
| `evidence-rules` | 任何要输出数字或结论的回答 | 每个数字必带 `source/timestamp/metric_version`；`status != ok` 的降级话术；禁止补全 | 常驻 |
| `anomaly-triage` | 异常事件、分级、归因 | 分级规则、归因检查清单、升级到设备/工艺的条件 | 按需 |
| `shift-handover-format` | 交接班、班前简报 | 固定段落、必填项、字数与语气、归档规则 | 按需 |
| `plant-terms` | 出现厂内黑话、别名、事件码、线体简称 | 黑话 → 标准 ID 映射表 | 按需 |

**渐进式披露**：启动只加载各技能的 `description`（封面）；命中才读 `SKILL.md` 正文；大段规范、案例、模板放 `references/`（本期预留目录）。**一个技能只做一类事**，避免触发混乱。

> `kpi-glossary` 与 `evidence-rules` 是「安全类技能」，建议在主 Agent 与两个子 Agent 中强制挂载，而不是依赖语义匹配。

## 3. Tool / MCP 层（4 个只读 Server，12 个工具）

完整 JSON Schema 见 [`tools/mcp-tool-schemas.json`](../tools/mcp-tool-schemas.json)。

### 3.1 `mcp-kpi` — KPI 只读查询

| 工具 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `get_kpi_snapshot` | `line_id`, `shift_id?` | UPH / NTF / Retest 现值、目标值、达成率、环比 | 全部取自监控系统，不重算 |
| `get_kpi_trend` | `line_id`, `metric`, `window` | 时序点列 | 供归因 Agent 看走势 |
| `compare_shift` | `line_id`, `shift_a`, `shift_b`, `metric` | 差值、变化率、结论标记 | **确定性比较，不让模型做减法** |

### 3.2 `mcp-events` — 异常事件

| 工具 | 参数 | 返回 |
|---|---|---|
| `get_active_anomalies` | `line_id`, `severity?` | 监控系统已算出的异常列表（`event_id` / 起止 / 代码 / 设备 / 状态） |
| `get_anomaly_detail` | `event_id` | 事件详情与关联的原始记录链接 |

### 3.3 `mcp-orders` — 业务上下文

| 工具 | 参数 | 返回 |
|---|---|---|
| `get_work_order` | `line_id`, `shift_id?` | 当前工单、SKU、计划量、报工进度 |
| `get_wip_status` | `line_id`, `station_id?` | 在制与工位状态 |
| `get_test_records` | `sku`, `window`, `result?` | 测试明细（归因 NTF / Retest 用） |
| `get_equipment_history` | `equipment_id`, `window` | 设备事件史 |
| `get_maintenance_log` | `equipment_id`, `window` | 维修与保养记录 |

### 3.4 `mcp-knowledge` — 本地知识

| 工具 | 参数 | 返回 |
|---|---|---|
| `search_sop` | `query`, `top_k?` | SOP / 工艺卡片段 + 文档出处 |
| `get_similar_cases` | `event_code`, `top_k?` | 历史相似案例 + 处置记录 |

### 3.5 统一返回体（所有工具强制）

```json
{
  "data": { "...": "业务字段" },
  "source": "monitoring-system://kpi/snapshot?line=L03",
  "timestamp": "2026-11-11T22:30:00+08:00",
  "metric_version": "kpi-2026.11",
  "status": "ok | stale | unavailable",
  "trace_id": "req-8f31c2"
}
```

### 3.6 MCP Server 统一收口的横切逻辑

| 能力 | 规则 |
|---|---|
| 鉴权 | 从登录态取 `user_id/role`，在 Server 内过滤 `line_id`；越权返回空 `data` 并写审计 |
| 白名单 | 只暴露上表 12 个工具；任何写/控制/下发工具不注册 |
| 参数校验 | JSON Schema 强校验；`line_id`/`event_id` 枚举与格式校验；时间窗上限（如 ≤ 31 天） |
| 限流 / 超时 | 单用户 QPS 限制；单次查询超时 3 s，超时返回 `status=unavailable` 而非部分数据 |
| 降级 | 监控系统不可用时返回 `status=unavailable` + 最后成功时间戳，不返回旧数值 |
| 审计 | 每次调用记录 `user / tool / 参数摘要 / status / 耗时 / trace_id` |
| 缓存 | 只读短缓存（如 KPI 快照 5~10 s），缓存命中也必须带原始 `timestamp` |

> 用 MCP 的核心价值：监控系统接口变了**只改 Server**，Agent / SKILL / 工作流都不动；权限与安全边界不依赖提示词约束。

## 4. 工作流层（3 条固定路径）

定义见 [`workflows/workflows.yaml`](../workflows/workflows.yaml)。

| 工作流 | 触发 | 步骤 | SLA | 失败降级 |
|---|---|---|---|---|
| `line-snapshot` 现状速览 | 快捷按钮 /「X 号线现在怎么样」 | `get_kpi_snapshot` → `get_active_anomalies` → `get_work_order` → 模板渲染 → 主 Agent 润色 | 2 s | 任一工具 `unavailable` → 该块显示降级说明，其余块照常 |
| `kpi-qa` KPI 问答 | 具体指标提问 / 班次对比 / 术语查询 | 意图槽位填充 → `get_kpi_snapshot` 或 `compare_shift` 或 `search_sop` → 模板 | 2 s | 同上；口径版本不一致时禁用对比 |
| `pre-shift` 班前简报 | 定时（班前 15 分钟） | 拉上一班遗留 + 本班计划 + 当前异常 → 套简报模板 | 分钟级 | 生成失败发站内提示，不静默跳过 |

**工作流与 Agent 的分界**：工具数量 ≤ 3、顺序确定、无需运行中判断 → 工作流；需要「根据上一步结果决定下一步查什么」→ 子 Agent。

## 5. 支撑服务

### 5.1 上下文构建器

- 从登录态解析：`user_id / role / line_ids[] / shift_id / 班组 / 当前时间窗`；
- 用户问题里的「3 号线」「A 班」经 `plant-terms` 映射为标准 ID 后注入；
- **未授权 `line_id` 直接在此拦截**，不进入工具层；
- 近期事件短缓存，避免同一异常反复拉取。

### 5.2 事件触发器（路径 B）

```
监控事件 → 规范化(event_id, line_id, code, severity, ts)
        → 去重（同 event_id + 同状态，窗口 60 s）
        → 分级（critical / warning / info，按 code 映射表）
        → 节流（同线同码 5 分钟内最多 1 张新卡，其余合并计数）
        → 生成卡片（规则引擎，纯模板，不调 LLM）
        → WebSocket/SSE 推 Web（常开看板页）
        → 可选：异步让 LLM 补一句解释，失败不影响卡片
```

断线重连后按 `last_event_id` 回放；事件风暴以合并计数保护页面。

### 5.3 证据与审计服务

| 记录类型 | 关键字段 |
|---|---|
| 问答记录 | `trace_id, user, question, route, answer, evidence[], model_version, latency` |
| 工具调用 | `trace_id, tool, args_digest, status, source, timestamp, metric_version, latency` |
| 写操作（三期） | `trace_id, user, action, before/after, approver, confirmed_at` |
| 口径变更 | `metric_version, changed_by, changed_at, diff, approvers[]` |

每个 `evidence` 项提供可点击的原始记录 URL + 三要素（来源/时间戳/口径版本）。

### 5.4 Web 应用

页面与交互见 [`web/web-ui-spec.md`](../web/web-ui-spec.md)：总览、问答、异常卡片、交接班、后台；站内 WebSocket/SSE；响应式适配工位机与平板。

## 6. 配置文件

[`config/plant-agent.yaml`](../config/plant-agent.yaml) 包含：

| 段 | 内容 |
|---|---|
| `runtime` | 本地 LLM / 向量库 endpoint（占位）、并发、超时、模型版本 |
| `metric_versions` | 当前口径版本、各指标定义引用、生效时间、审批人 |
| `acl` | 角色 → 线体授权矩阵、默认拒绝 |
| `degradation` | 各数据源超时/重试/缓存/降级文案 |
| `event_rules` | 分级映射、去重窗口、节流规则、回放策略 |
| `audit` | 日志保留期、脱敏字段、采样策略 |

## 7. 部件依赖与最小实现顺序

```
config 口径版本 + ACL  （先签字）
   ↓
tools/mcp-*.json + 4 个 Server 适配层   （先跑通取数）
   ↓
workflows 3 条 + 事件触发器 + 证据审计  （无 LLM 也能出总览与卡片）
   ↓
skills 5 份 + agents 3 个定义          （接入本地 LLM）
   ↓
Web 前端                              （最后串起来）
```

> **不要从提示词/模型开始做**。先让「无 AI」的总览与异常卡片跑通，再往上加 Agent——这样任何回答出错时，能立刻判断是数据问题还是模型问题。
