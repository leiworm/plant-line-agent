# 04 · 落地路线与验收

## 1. 分期计划

| 期 | 目标 | 交付物 | 退出条件（缺一不进下一期） |
|---|---|---|---|
| **P0 调研与口径确认** | 把「数据能不能取、口径是什么」钉死 | ① 监控系统接口清单与鉴权方式；② UPH/NTF/Retest 口径签字表；③ 试点线体与班次定义；④ 本仓库 v1.0 需求/架构评审通过 | Q-1~Q-4（见 01 文档第 5 节）全部关闭；口径经生产+设备+IE 三方签字 |
| **P1 MVP（1 条线、只读）** | 让班组长愿意在交接班时真的用 | 4 个 MCP Server + 3 条工作流 + 事件卡片 + Web 总览/问答/异常 + 5 份 SKILL + 主 Agent + 审计 | AC-1~AC-6、AC-9 通过；连续 5 个班次实际试用（AC-10） |
| **P2 归因与复盘** | 回答「为什么」、生成交接班草稿 | 异常归因子 Agent、班次复盘子 Agent、本地知识库、班前简报、交接班归档 | AC-7、AC-8 通过；归因结论抽查无「无证据断言」 |
| **P3 闭环与扩展** | 多线多班、有限写操作 | 多线授权、跨班次对比、异常处置状态、经人工审批的写工具（如补录停机原因） | 每次写操作 100% 有审批人与审计；安全评审通过 |

> 设备参数下发 / 自动控产线 **不列入任何一期**，建议永久排除。

## 2. MVP 范围（严格遵守）

**做**：现状速览、三项 KPI 问答与班次比较、异常列表与事件卡片、站内推送、证据链、降级、审计、SSO 与线体隔离、后台基础配置。

**不做**：归因、SOP 检索、交接班草稿、跨线对比、任何写操作、任何外部通知。

## 3. MVP 验收清单

```
数据契约
[ ] 12 个工具全部返回 source / timestamp / metric_version / status
[ ] 工具清单中无任何写/控制/下发工具（AC-9）
[ ] 越权 line_id 返回空 data 并写审计（AC-4）
[ ] 口径版本表已由三方签字，配置与技能文档一致

正确性
[ ] 抽 30 个时间点，Agent 输出与监控系统报表完全一致（AC-1）
[ ] 回答中每个数字可点击回溯（AC-2）
[ ] 模型不产生任何未经工具返回的数值

可用性与降级
[ ] 断源 30 s：显示降级提示且页面不出现数值（AC-3）
[ ] 100 事件/3 min：无重复卡片、页面不卡死（AC-5）
[ ] 现状速览 P95 ≤ 2 s（AC-6）
[ ] 首屏 ≤ 3 s；工位机与平板浏览器均可用

现场
[ ] 2~3 位班组长完成 10 分钟内的上手试用
[ ] 连续 5 个班次交接班实际使用（AC-10）
[ ] 「打开 Web 到看清现状 ≤ 10 秒」现场实测达成

安全与部署
[ ] 全链路厂内，无任何外网调用（抓包验证）
[ ] SSO 接入、线体级隔离生效
[ ] 审计日志覆盖全部问答与工具调用
```

## 4. 测试用例（示例）

| 用例 | 输入 | 期望 |
|---|---|---|
| T-01 正常现状 | 「3 号线现在怎么样」 | 走 `line-snapshot`；3 个数字各带证据；≤ 2 s |
| T-02 班次比较 | 「NTF 跟上一班比」 | 走 `compare_shift`；差值由工具返回，模型未自行计算 |
| T-03 数据源不可用 | 断开监控接口 | 「数据源不可用，最后更新 xx」，无数值、无补全 |
| T-04 数据陈旧 | `status=stale` | 明确提示数据滞后，仍展示原始时间戳 |
| T-05 越权 | 班组长 A 问 5 号线 | 返回无权限/空结果，审计记录一条 |
| T-06 事件风暴 | 3 分钟 100 条同码事件 | 合并为 1 张卡 + 计数，页面正常 |
| T-07 口径变更 | 把 `kpi-2026.11` 升到 `kpi-2026.12` | 跨版本对比被禁用并提示 |
| T-08 幻觉诱导 | 「你估计一下今天产量大概多少」 | 拒绝估算，只给已记录的报工数据 |
| T-09 归因无证据 | 构造无匹配案例的异常 | 输出 `unknowns`，不编造原因 |
| T-10 黑话 | 用厂内简称点名线体 | `plant-terms` 正确映射到标准 ID |
| T-11 断线重连 | 关闭 WS 30 s 后恢复 | 按 `last_event_id` 回放，不丢事件 |
| T-12 模型不可用 | 停掉本地 LLM | 总览与事件卡片仍可用；仅问答区提示不可用 |

> T-12 是架构是否合理的关键检验：**没有 AI 时，看板和告警必须照常工作**。

## 5. 风险登记

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| RK-1 | 监控系统无对外只读接口 / 只允许导出文件 | 中 | **高**：MCP 层无法取数 | P0 首项验证；备选：定时落库到厂内只读副本 |
| RK-2 | UPH/NTF/Retest 口径与报表不一致 | 中 | **高**：结论不可信 | 三方签字 + 口径版本 + AC-1 逐点比对 |
| RK-3 | 停机原因人工填写不规范、事件码不统一 | 高 | 中高：归因质量差 | 一期不依赖原因字段做结论；`unknowns` 明确标注 |
| RK-4 | 本地模型能力不足，路由误判 | 中 | 中 | 高频场景走工作流；路由规则硬编码优先；保留快捷按钮兜底 |
| RK-5 | 纯 Web 无旁路导致离屏漏告警 | 高 | 中 | 已接受；常开看板页 + 浏览器通知 + 交接班补看未闭环项 |
| RK-6 | 按 IT 视角设计，班组长看不懂 | 中 | 中 | 一屏卡片 + 大按钮 + 厂内术语；2~3 位班组长全程参与 |
| RK-7 | 范围蔓延到「自动控制产线」 | 中 | **高**（安全） | 白名单只读 + 安全评审 + 本文档列为排除项 |
| RK-8 | 事件风暴压垮前端 / 模型 | 中 | 中 | 去重分级节流 + 卡片不经 LLM |

## 7. 上线检查表

- [ ] Q-1~Q-4 已关闭，口径签字版已归档
- [ ] 全链路抓包确认无出厂流量、无第三方遥测
- [ ] 工具白名单只读，写/控制工具为零
- [ ] 故障注入（断源、断模型、事件风暴、断线重连）全部通过
- [ ] 审计日志可查询、可导出，保留期符合厂规
- [ ] 回滚方案：关闭 Agent 问答后，监控系统原报表与看板仍可正常使用
- [ ] 班组长培训：10 分钟上手卡 + 常开看板页设置说明
- [ ] 明确告知「浏览器关闭时收不到新告警」

## 8. 迭代原则

1. 失败只改出错那一块（工具 / 技能 / 工作流 / Agent），不要整体重写提示词。
2. 口径变更 → 只改 `kpi-glossary` + `metric_version`，框架不动。
3. 每次成功的新场景，先跑通固定工作流，确实需要动态判断再升级为子 Agent。
4. 任何新工具上线前先确认：返回体是否带三要素、是否在只读白名单内、是否可追溯。
