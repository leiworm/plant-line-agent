# 厂内术语与 ID 映射

> 目的：班组长不会说 `L03-ST-07`，他们说「3 号线测试位」。
> 本技能负责把人的说法翻成标准 ID；**解析不了就问，不要猜**。

## 1. 映射原则

1. 先精确匹配，再别名匹配，最后才考虑模糊匹配。
2. 模糊匹配命中多个候选时，**列出候选让用户确认**，不擅自选第一个。
3. 解析出的 `line_id` 必须在 `context.authorized_line_ids` 内，否则按越权处理。
4. 映射表未收录的说法 → 记入「未识别术语」日志，供后台补充；回答里用用户原话复述并说明无法定位。
5. 映射表变更留版本与时间，由后台维护，**不改 Agent 代码**。

## 3. 解析输出

```json
{
  "resolved": {"line_id": "L03", "shift_id": "2026-11-11-D", "equipment_id": null},
  "unresolved": ["老测试机"],
  "ambiguities": [],
  "authorized": true
}
```

- `unresolved` 非空 → 主 Agent 用一句话请用户确认，不调用工具。
- `authorized=false` → 直接拒绝，写审计，不尝试其他线体。

## 4. 回答时的反向翻译

向用户展示时用**厂内习惯叫法**（「3 号线」），证据与后台链接里用标准 ID（`L03`）。不要在回答里堆标准编码。
