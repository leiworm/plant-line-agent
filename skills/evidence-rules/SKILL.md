# 证据与降级规则

> 本技能是**强制挂载**技能（主 Agent 与两个子 Agent 均不得依赖语义匹配），用于保证「每个数字都能点回监控系统原始记录」。

## 1. 证据三要素（缺一即拦截答案）

每个数值 / 事实性结论必须携带：

| 字段 | 说明 |
|---|---|
| `source` | 数据来源标识 + 可点击的原始记录 URL |
| `timestamp` | 该数据的产生时间（不是回答时间），带时区 |
| `metric_version` | 口径版本，如 `kpi-2026.11` |

另外记录 `trace_id` 用于串联问答与工具调用日志。

**校验规则**：答案输出前由证据服务逐项检查；发现「有数值但无三要素」→ **删除该数值**，而不是补一个来源。

## 2. 工具返回状态处理

| `status` | 处理方式 |
|---|---|
| `ok` | 正常使用，附三要素 |
| `partial` | 只使用已返回的部分；明确写出哪一块缺失 |
| `stale` | 展示数据但显著标注「数据滞后，最后更新 {timestamp}」，不做实时结论 |
| `unavailable` | 不输出任何数值，使用降级话术 |

## 3. 降级话术（统一，不要自由发挥）

```
数据源不可用，最后更新 {timestamp}。该部分数据本次未展示。
```
```
当前数据滞后（{timestamp}），以下数值仅作参考，不代表实时状态。
```
```
缺少 {字段名}，无法判断 {问题}。需现场确认后补充。
```

## 4. 禁止清单（出现即视为缺陷）

- 编造数值、单位、百分比、时间、事件码；
- 用历史值 / 上一班值 / 平均值 / 缓存值冒充实时值；
- 用「大约」「估计」「按经验」给数字；
- 把模型推断写成监控系统结论；
- 把相关性写成因果（「因此导致」）；
- 隐藏 `unavailable` 状态，让回答看起来完整；
- 用不同 `metric_version` 的数据做对比而不提示；
- 引用没有 `source` 的 SOP / 案例片段。

## 5. 表述要求

- 先给结论，再给证据，最后给「数据说明」。
- 数值照抄工具返回值，保留原单位与精度，不换算、不四舍五入。
- 不确定就写不确定：`unknowns` / 「需现场确认」是合格答案，猜一个原因是缺陷。
- 建议与指令区分：用「建议按 SOP 检查……」，不用「把参数调到……」。

## 6. 审计要求

每次问答与工具调用都要能回答四个问题：**谁问的 / 调了哪些工具 / 数据来自哪里 / 输出了什么**。缺任何一项，审计服务应拒绝该次回答落库并告警。
