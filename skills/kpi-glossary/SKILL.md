# 产线 KPI 口径

> **本技能是整个系统最重要的文件**：口径错，答案全错。
> 当前版本：`kpi-2026.11`（与 `config/plant-agent.yaml → metric_versions` 保持一致）。
> **⚠️ 下表中的定义、目标值、阈值为占位假设，须经生产 + 设备 + IE 三方签字后方可投产。**

## 核心原则

1. **Agent 不计算 KPI**。UPH / NTF / Retest、达成率、环比、班次差值一律取自监控系统或 `compare_shift` 工具的返回值。
2. **不自行推算**：不得用「当前产量 ÷ 已过时间」估算 UPH，不得用部分时段数据外推整班。
3. **口径以监控系统报表为准**。本技能只是把报表口径翻译成人话；两者不一致时，以监控系统为准并上报口径问题。
4. **跨口径版本禁止直接比较**。发现 `metric_version` 不一致，按 `evidence-rules` 提示并禁用对比。

## 指标定义（待签字）

| 指标 | 暂定含义 | 统计窗口 | 目标值来源 | 数据工具 |
|---|---|---|---|---|
| UPH | Units Per Hour，单位小时产出 | 当前班次累计（班起至查询时刻） | 排产计划 | `get_kpi_snapshot` / `get_kpi_trend` |
| NTF | No Trouble Found，送修 / 复测未复现占比 | 当前班次累计 | 待确认 | 同上 |
| Retest | 复测率 / 复测台数占比 | 当前班次累计 | 待确认 | 同上 |

**待确认明细（Q-1 / Q-2）**
- NTF 的分子分母：按台数还是按次数？是否含复测合格？
- Retest 与 NTF 是否互斥、是否会重复计数？
- 跨班次边界（夜班跨日）、换型时段是否计入分母？
- 返工、重测、暂停时段的归属规则。
- 目标值与告警阈值是固定值还是按 SKU / 工单动态给定。

## 常见误读（回答时必须避免）

| 误读 | 正确表述 |
|---|---|
| 把「当前瞬时 UPH」当成「本班累计 UPH」 | 明确说明统计窗口，并附时间戳 |
| 把 NTF 升高直接归因为「产品质量变差」 | NTF 高也可能来自测试工位、治具、判定标准变化；只列可能性与证据 |
| 把 Retest 高说成「不良率高」 | 两者口径不同，不得混用 |
| 用上一班的值填充本班缺失数据 | 数据缺失就说缺失 |
| 用不同口径版本的历史值做趋势对比 | 禁用并提示版本差异 |
| 把「达成率 98%」说成「差 2% 就达标」之外的推断 | 不做达标预测 |

## 回答模板

```
【结论】本班 UPH {工具返回值}，目标 {工具返回值}，达成率 {工具返回值}。
【对比】较上一班 {compare_shift 返回的差值/变化率}。
【口径】统计窗口：{窗口}；口径版本：{metric_version}；数据时间：{timestamp}。
【来源】{可点击的监控系统原始记录链接}
```

## 口径变更流程

1. 生产 / 设备 / IE 三方确认新定义与生效时间 → 更新本文件与 `config/plant-agent.yaml`。
2. 递增 `metric_version`（如 `kpi-2026.12`），记录变更人、时间、diff、审批人。
3. 审计服务写入口径变更记录；跨版本对比自动禁用。
4. **框架、Agent、工具代码均不修改** —— 这正是把口径放在技能里的目的。
