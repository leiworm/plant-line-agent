# 异常分级与归因检查清单

> 异常事件**由既有监控系统计算得出**。本技能只规定「如何分级、按什么顺序查、话怎么说」，**不重新判定是否异常、不改事件等级来源**。

## 1. 分级规则（映射表由后台维护）

| 级别 | 典型情形 | Web 呈现 | 处理要求 |
|---|---|---|---|
| `critical` | 线体停机、安全相关、监控系统标记最高级 | 红卡 + 置顶 + 浏览器通知（如已授权） | 立即查看，交接班必须列明 |
| `warning` | 节拍偏离、KPI 越阈值、单工位异常 | 黄卡 | 本班内确认 |
| `info` | 换型、计划停机、一般提示 | 灰卡 / 仅列表 | 记录即可 |

- 级别以**监控系统事件自带等级**为准；映射表只做「事件码 → 展示级别」的翻译，不做升降级判断。
- 级别未知时按 `warning` 展示并标注「等级未映射，请后台补配置」，不静默忽略。

## 2. 归因检查清单（`anomaly-rca` 必须按序执行）

```
[ ] 1. 事件基本信息：event_id / 事件码 / 起止时间 / 设备 / 工位 / 当前状态
[ ] 2. 时间线：指标偏离从何时开始？是否早于事件上报时间？
[ ] 3. 生产上下文：是否换型、换 SKU、换工单、换班？计划停机是否重叠？
[ ] 4. 测试明细：NTF / Retest 相关记录是否集中在某工位、某治具、某批次？
[ ] 5. 设备上下文：近期维修、保养、备件更换、同类事件复发？
[ ] 6. 历史案例：同事件码过去如何处置、闭环了没有？
[ ] 7. SOP：对应的检查步骤、责任人角色、禁止动作
[ ] 8. 缺口：哪些字段为空、哪些数据源不可用 → 写进 unknowns
```

## 3. 升级条件（只给建议，不自动执行）

| 条件 | 建议对象 |
|---|---|
| 同设备 24 h 内第 3 次同类事件 | 设备工程师 |
| 偏离集中在某 SKU / 批次 | 工艺 + 质量 |
| 测试明细集中在单一治具 / 测试工位 | 测试 / 设备 |
| 事件持续超过阈值（按后台配置） | 生产主管 |
| 原因字段为空且无相似案例 | 明确写「需现场确认」，不给结论 |

## 4. 输出四段式（缺段不合格）

```
【可能原因】按证据强弱列 1~3 条，每条标注 high/medium/low 并引用证据编号
【证据】编号列表，每条含来源 + 时间戳 + 口径版本
【建议】按 SOP 的检查步骤与应联系的角色；明确「建议」而非指令
【不确定项】缺失字段、不可用数据源、无法排除的可能性
```

## 5. 禁止事项

- 说「一定是 / 肯定是」，把相关性写成因果；
- 编造停机原因、用常识补全缺失字段；
- 给设备参数调整值、启停指令、工艺变更指令；
- 修改事件级别、关闭异常、回写监控系统；
- 重复上报同一事件（去重由事件触发器负责，窗口 60 s）。

## 6. 话术要求

先说「哪条线 / 哪台设备 / 多久 / 什么代码」，再说可能性，最后说还缺什么。短句、厂内叫法、不写客套话。数据不可用时统一按 `evidence-rules` 的降级话术。
