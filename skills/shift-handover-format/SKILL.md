# 交接班简报格式

> 目标：让下一班在 1 分钟内看清「本班做成什么、还剩什么问题」。
> 本技能只管**格式与必填项**，数据全部来自 MCP 工具，不得补写。

## 固定结构（顺序不可调整）

```markdown
# {line_id} {shift_id} 交接班（{date}）

## 1. 本班结果
- UPH：{值} / 目标 {值} / 达成率 {值}
- NTF：{值}　Retest：{值}
- 工单：{工单号 / SKU}，计划 {值}，报工 {值}
- 较上一班：{compare_shift 返回值}

## 2. 异常与处置
| 时间 | 设备/工位 | 事件码 | 持续 | 当前状态 | 处置记录 |
|---|---|---|---|---|---|
（每条带 event_id 与原始记录链接）

## 3. 未闭环事项（下一班必须接手）
- [ ] {事项}｜建议责任角色：{设备/工艺/质量}｜关联 event_id

## 4. 需下一班注意
- {换型计划 / 物料 / 治具 / 待确认事项，仅写有数据支撑的内容}

## 5. 数据说明
- 口径版本：{metric_version}
- 数据时间：{timestamp}
- 不可用数据源：{列表；无则写「无」}
```

## 必填项（缺一不允许归档）

1. `line_id` / `shift_id` / `date`
2. 三项 KPI 现值（或明确标注「数据源不可用」）
3. 工单与 SKU（或标注不可用）
4. 异常清单（无异常写「本班无记录异常」，不得留空）
5. 未闭环事项清单（无则写「无」）
6. 口径版本 + 数据时间 + 不可用数据源说明
7. 确认人（班组长）与确认时间 —— **由人工在 Web 上点确认，Agent 不得代填**

## 写作规则

- 短句、名词优先，不写形容词与主观评价（不写「表现良好」「略有改善」）。
- 数值一律照抄工具返回值，保留原单位与精度，不四舍五入、不换算。
- 每个数值后附可点击证据标记（见 `evidence-rules`）。
- 推断性内容（原因、预测、责任归属）**一律不写**；只写记录和已确认的处置。
- 原因字段为空时写「停机原因未录入」，不得猜测。
- 全文控制在 1 屏内；超出部分放折叠区「明细」。

## 归档规则

1. 子 Agent 只生成**草稿**（`status=draft`）。
2. 班组长在 Web 上编辑、补录、确认后才变为 `archived`。
3. 归档后不可覆盖；修订生成新版本并保留修订人与时间。
4. 归档记录写入审计服务，可按线体 / 班次 / 日期查询。
5. 草稿在服务重启后不丢失（落盘保存）。

## 班前简报的差异

班前简报复用第 1、3、4、5 段，但第 1 段改为「上一班结果 + 本班计划」，第 3 段改为「上一班遗留事项」，不写本班结果。
